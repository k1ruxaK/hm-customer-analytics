# H&M Customer Analytics

Анализ клиентской базы H&M на 31.8 млн транзакций: когортное удержание,
RFM-сегментация, анализ каналов продаж, дизайн A/B-теста и модель оттока.

> Данные — публичный датасет [H&M Personalized Fashion Recommendations](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/data) (Kaggle).
> Цены в датасете нормализованы, поэтому выручка везде указана в условных единицах.

## Главные выводы

- **Концентрация выручки (Парето).** Champions — 19.7% клиентов, но 55.1%
  выручки. Топ-2 сегмента (Champions + Loyal) — 40% клиентов и 77% выручки.
  Lost — крупнейший сегмент по числу (25.3%), но лишь 4.7% выручки.
- **Истинное удержание новых клиентов ≈ 13–15% на M+1**, а не 40%, как
  показывают ранние когорты: те завышены из-за left truncation (в них попали
  клиенты с историей до начала данных). Удержание не падает до нуля —
  стабилизируется на 10–13% и держится больше года.
- **COVID — период-эффект, а не когортный.** Просадка весной 2020 видна по
  диагонали тепловой карты (у всех когорт сразу): качество привлечения в
  пандемию не упало, упала интенсивность покупок (выручка −8.9% год к году).
- **Omnichannel-клиенты дают 67.7% выручки при 35.5% базы.** Но это маркер
  ценности, а не доказанная причина: omnichannel по определению требует ≥2
  покупок, поэтому категория смещена в сторону активных клиентов.
- **Модель оттока: ROC-AUC 0.83, lift топ-10% = 1.5.** Главный драйвер оттока —
  recency, главный фактор удержания — разнообразие покупок. Членство в клубе
  снижает отток, но вторично.

## Стек

- **Хранилище:** ClickHouse (колоночная СУБД) в Docker — выбрана под объём
  31.8 млн строк; колоночное сжатие дало ~5× (3.4 GB → 670 MB).
- **Анализ:** Python — pandas, scikit-learn, LightGBM, statsmodels, matplotlib;
  подключение к ClickHouse через clickhouse-connect.
- **BI:** Apache Superset (подключён к ClickHouse напрямую).
- **Инфраструктура:** Docker Compose, Git, SQL.

## Аналитические блоки

1. **EDA** (`01_eda.ipynb`) — качество данных, профилирование, проверка
   маппинга каналов через COVID, формулировка гипотез.
2. **Когортный анализ** (`02_cohort_analysis.ipynb`) — удержание по месячным
   когортам; разделение когортного, lifecycle и период-эффектов.
3. **RFM-сегментация** (`03_rfm_segmentation.ipynb`) — квинтили R/F/M, 6
   сегментов, анализ концентрации выручки.
4. **Анализ каналов** (`04_channels.ipynb`) — omnichannel vs single-channel
   с разбором причинности.
5. **A/B-тест: дизайн** (`05_ab_test_design.ipynb`) — расчёт размера выборки
   (statsmodels), стратификация, A/A-проверка, z-тест и bootstrap. На
   исторических данных реальный тест невозможен, поэтому показаны методология
   планирования и процедура анализа на симулированном эффекте.
6. **Прогноз оттока** (`06_churn_model.ipynb`) — бинарная классификация
   (отток = нет покупок 3 месяца), сравнение логрега и LightGBM,
   feature importance, lift. Для продакшена выбран логрег: при сопоставимом
   качестве он интерпретируем.

## Как запустить

1. Скачать датасет с Kaggle, положить CSV в `data/`.
2. Поднять ClickHouse и Superset:
```bash
   docker compose up -d --build
```
3. Создать таблицы и загрузить данные (`sql/01_create_tables.sql`,
   `sql/02_load_data.sql`).
4. Запустить ноутбуки из `notebooks/` (ClickHouse на `localhost:8123`).
5. Дашборд: Superset на `http://localhost:8088`.

## Замечания

- Цены нормализованы — денежные метрики в условных единицах, важны доли и
  относительные значения.
- Дубли транзакций (~9%) — реальные повторные покупки одного товара, сохранены.
- Во всех моделях окна признаков и target разнесены во времени для защиты от
  data leakage.
